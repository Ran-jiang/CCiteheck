# CCiteheck 任务窗格设计约定

本文档对应 `apps/word_addin/assets/taskpane.css` 的 token 与结果页信息架构。修改样式时保持本文档同步。

## 设计 Token(:root)

- 品牌色:Fluent Blue `--brand-bg #0F6CBD`、`--brand-bg-hover #115EA3`、`--brand-bg-pressed #0F548C`、`--brand-fg`、`--brand-bg-tint #EBF3FC`
- 中性色:`--fg-1/2/3`、`--bg-1 #fff`、`--bg-2 #FAFAFA`、`--stroke-1/2`
- 状态色:`--success-*`、`--danger-*`、`--warning-*`(仅用于 badge / 计数及引用语义块)
- 阴影仅 toast / 浮层可用;卡片一律无阴影
- 圆角:卡片 8px,块级引用/按钮 4–6px,badge 999px
- 字号阶梯:正文 14px/22;辅助 12–13px(18–20 行高);引用条名 15px/22 加粗;页面标题 16px/24

## 结果页信息架构

- 一处文书原文(一个 display group)= 一张外层卡片;卡内禁止嵌套边框卡片
- 卡片内区块一律无分区小标题,靠视觉样式区分:
  - 文书原文:浅灰底块,块内左上"文书原文"、右上"定位原文"
  - 权威来源:浅蓝底 + 3px 品牌蓝竖条,右下"查看权威原文 ↗"(URL 不外露)
  - 建议:仅展示自然语言正文，不展示红删绿标 diff
  - 引用对照:原引用用蓝色块，候选修正引用用绿色块
- 业务状态(仅 UI 展示层合并,数据层 review/bug 不变):
  - `issue` → 未通过(默认完全展开)
  - `review` / `bug` → 待核实(卡头 + 一行原因,点击展开)
  - `pass` → 已通过(默认一行,点击展开证据)
- 多引聚合卡:卡头"本段共 N 条引用" + 按状态着色的聚合计数;引用项之间细分割线、无编号;内部转引用 `承前条款 · ` / `内部转引 · ` 前缀 + 16px 左缩进
- 重新核查位于结果页标题区;结果页不使用底部固定或嵌套滚动区
- 筛选、定位与修订按钮保持至少 44px 点击高度
