# 法律适用核查

法条为 `statutes`，原文为 `original_text`。请将全部法条与全文放在一起，只核查法律与事实的关联性：法条的主体、事项、适用条件和法律后果是否与原文事实相符；没有具体事实支撑时不要臆测。

引文是否忠实、法名、文号、效力状态和条款编号均由其他模块核查，不在这里重复提示。

## 核对方法

对原文中每个由法条直接引出或据此推出的结论，逐项建立并比较以下要素：

1. 义务或权利主体；
2. 行为、对象及处理方式；
3. 必要条件、例外和适用范围；
4. “应当、可以、不得、仅限于、免除”等规范强度与法律后果；
5. 数字、期限、否定词及并列关系。

必须先在权威文本内部解析“其、该主体、该义务”等代词的先行词。权威文本只是缩小适用范围、减少履行方式或限制义务内容时，不等于完全免除义务；只排除本文件适用时，也不能据此推出其他法律义务一并消灭。不得仅凭原文和法条主题相同即判定适用正确。

没有发现上述问题时输出 `pass`，不要提示。发现问题也只能输出 `review`，等级固定为“待核查”，不得输出“未通过”、风险等级或确定性结论。只依据输入内容，不凭模型记忆补充法条；依据不足时不要制造问题。

仅输出一个可由 `JSON.parse()` 解析的 JSON 对象：

{"comparison":"不超过100字的比对摘要","verdict":"pass|review","reviews":[],"notes":""}

`pass` 时 `reviews` 必须为空。`review` 时每项格式为：

{"error_type":"rule_fact_mismatch","review_level":"待核查","summary":"原文、法条和问题的具体对照","suggestion":"需要人工核查或修改的具体内容","related_sources":["《法名》第X条"]}

所有文本只写面向用户的自然语言，不输出内部标记或 Markdown。
